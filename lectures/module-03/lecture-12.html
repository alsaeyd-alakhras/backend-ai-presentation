Validation Basics02 / 09
أبسط نقطة بداية: validation مباشر داخل Controller
DIRECT VALIDATION
PHP
$validated = $request->validate([ 'name' => 'required|string|min:3|max:255', 'email' => 'required|email|unique:users,email', 'price' => 'required|numeric|min:0.01', 'stock' => 'required|integer|min:0', ]);
WHAT HAPPENS
إذا فشل التحقق يعود المستخدم تلقائياً مع الأخطاء والقيم القديمة.
`$validated` يحتوي فقط الحقول المسموح بها في القواعد.
ممتاز للبدايات أو النماذج الصغيرة.

Unique Ignore05 / 09
في التعديل: `unique` مع ignore
UPDATE RULE
PHP
'name' => [ 'required', 'string', Rule::unique('products', 'name') ->ignore($this->product->id), ],
WHY
بدون `ignore` سيعتبر Laravel نفس اسم المنتج الحالي تكراراً.
هذا النمط أساسي في كل تحديث يعتمد على قيم فريدة.
نفس الفكرة تطبق على email والslug وأي unique field.

Custom Rules07 / 09
عندما لا تكفي القواعد الجاهزة: Custom Validation Rules
VALID SALE PRICE
PHP
class ValidSalePrice implements ValidationRule { public function validate(string $attribute, mixed $value, Closure $fail): void { $price = request('price'); if ($value && $price && $value >= $price) { $fail('سعر الخصم يجب أن يكون أقل من السعر الأصلي.'); } } }
ANOTHER REAL CASE
`SufficientStock` للتحقق أن الكمية المطلوبة لا تتجاوز المخزون.
هذا النوع من القواعد يجعل منطق التحقق reusable ونظيفاً.
ضعه داخل `app/Rules` ومرره داخل request ككائن rule.
