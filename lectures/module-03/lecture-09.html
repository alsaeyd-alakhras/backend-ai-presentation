Index Query03 / 08
بناء صفحة index مع البحث والفلترة
CONTROLLER
PHP
$products = Product::query() ->when($request->search, fn($q, $search) => $q->where('name', 'like', "%{$search}%") ) ->when($request->category, fn($q, $cat) => $q->where('category_id', $cat) ) ->latest() ->paginate(15) ->withQueryString();
WHY `when()`
يوفر بديلاً أنظف من `if/else` داخل الـ query.
يقرأ بسرعة: لو فيه قيمة طبّق الشرط، غير ذلك تجاهله.
يسهل إضافة فلاتر جديدة لاحقاً مثل السعر أو الحالة.
اجعل `Category::all()` منفصلة وواضحة حتى تستخدمها في الـ select بدون تكرار منطق داخل Blade.

Store05 / 08
الانتقال إلى create و store
VALIDATE + CREATE
PHP
$request->validate([ 'name' => 'required|string|max:255', 'category_id' => 'required|exists:categories,id', 'price' => 'required|numeric|min:0', 'stock' => 'required|integer|min:0', ]); Product::create([ 'name' => $request->name, 'category_id' => $request->category_id, 'slug' => Str::slug($request->name), 'price' => $request->price, 'stock' => $request->stock, 'is_active' => $request->boolean('is_active'), ]);
THINKING
ابدأ بـ validation مباشر ومختصر، ثم طوّره لاحقاً إلى Form Request.
توليد `slug` هنا مناسب كبداية قبل عزله في Service أو Observer.
استخدم `boolean('is_active')` بدلاً من افتراض قيم checkbox يدوياً.

Pagination06 / 08
فهم Pagination جيداً من البداية
`paginate()`
يعرض أرقام الصفحات كاملة.
مناسب للـ admin panels.
`simplePaginate()`
السابق/التالي فقط.
أخف عندما لا تحتاج total pages.
`cursorPaginate()`
أفضل للـ API وInfinite Scroll.
أخف على قواعد البيانات الكبيرة.
BLADE
{{ $products->withQueryString()->links() }} <p> عرض {{ $products->firstItem() }}-{{ $products->lastItem() }} من {{ $products->total() }} منتج </p>
