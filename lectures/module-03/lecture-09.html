Routing05 / 15
سطر واحد يولد routes كثيرة: Route::resource()
BEFORE
PHP
Route::get('/products', [ProductController::class, 'index']); Route::get('/products/create', [ProductController::class, 'create']); Route::post('/products', [ProductController::class, 'store']); Route::get('/products/{product}', [ProductController::class, 'show']); Route::get('/products/{product}/edit', [ProductController::class, 'edit']); Route::put('/products/{product}', [ProductController::class, 'update']); Route::delete('/products/{product}', [ProductController::class, 'destroy']);
AFTER + GROUP
PHP
Route::middleware('auth') ->prefix('admin') ->name('admin.') ->group(function () { Route::resource('products', ProductController::class); });
`middleware('auth')` يحمي كل routes المجموعة.
`prefix('admin')` يجعل الرابط يبدأ بـ `/admin`.
`name('admin.')` يجعل الأسماء تبدأ بـ `admin.products.*`.
Route Groups لا تضيف feature جديدة للمستخدم، لكنها تمنع الفوضى عندما تكبر لوحة التحكم.

Routing06 / 15
Named Routes و route:list: لا تحفظ الروابط من ذاكرتك
NAMED ROUTE USAGE
PHP
Route::get('/products/{product}', [ProductController::class, 'show']) ->name('products.show'); route('products.show', $product); route('admin.products.edit', $product);
الاسم يبقى ثابت حتى لو تغير الرابط لاحقاً.

Eloquent09 / 15
العمليات الأساسية لجلب البيانات
COMMON METHODS
PHP
Product::all(); Product::all(['id', 'name', 'price']); Product::find(5); Product::findOrFail(5); Product::first(); Product::latest()->first(); Product::orderBy('price', 'asc')->get();
WHEN TO USE
الدالةالاستخدام الأفضل
`all()`قوائم صغيرة أو lookup tables فقط
`find()`عندما تقبل `null` إذا لم يوجد السجل
`findOrFail()`داخل Controllers لصفحات التفاصيل والتعديل
`latest()`قوائم الإدارة والأحدث أولاً
`orderBy()`ترتيب واضح حسب السعر أو الاسم أو التاريخ
قاعدة عملية: في Controller غالباً اختر `findOrFail()` حتى تحصل على 404 طبيعي بدلاً من أخطاء مبهمة.

Model Safety11 / 15
حماية الـ Model: fillable و casts
FILLABLE
PHP
class Product extends Model { protected $fillable = [ 'category_id', 'name', 'slug', 'description', 'price', 'sale_price', 'stock', 'image', 'is_active' ]; }
WHY IT MATTERS
يمنع المستخدم من تمرير حقول لم تسمح بها مثل `is_admin` أو قيم حساسة.
يجعل `create()` و`update()` آمنين ومقصودين.
CASTS + ACCESSORS + MUTATORS
PHP
protected $casts = [ 'is_active' => 'boolean', 'price' => 'decimal:2', 'meta' => 'array', 'published_at' => 'datetime', ];
`casts` تضبط شكل البيانات تلقائياً عند القراءة والكتابة.
Accessor يضيف قيمة جاهزة مثل `formatted_price` للواجهة.
Mutator يعالج الإدخال قبل الحفظ مثل تنسيق الاسم.
`guarded` هو البديل المعاكس لـ `fillable`، لكن للمبتدئ `fillable` أوضح وأقرب للأمان.

Best Practice13 / 15
قرارات صغيرة تمنع فوضى كبيرة
DO THIS
استخدم Resource Controller عندما يكون عندك CRUD واضح.
اجعل روابط لوحة التحكم داخل group واحد بـ `prefix`, `name`, و`middleware`.
استخدم named routes داخل Blade والـ redirects.
ابدأ الاستعلامات القابلة للتوسع بـ `Product::query()`.
عرّف `fillable` و`casts` قبل أول `create()` أو `update()`.
AVOID
لا تكرر 7 routes يدوياً إذا كان `Route::resource()` مناسباً.
لا تكتب الروابط النصية في كل مكان ثم تبحث عنها عند التغيير.
لا تضع شروط البحث داخل Blade.
لا تستخدم `all()` لقائمة كبيرة ستحتاج pagination لاحقاً.
لا تؤجل حماية الـ Model إلى ما بعد حفظ البيانات.
هذه ليست قواعد تجميلية؛ هي ما يجعل CRUD القادم قابلاً للقراءة والتعديل.
