ORM vs SQL03 / 08
لماذا نستخدم Eloquent بدلاً من SQL الخام كل الوقت؟
RAW SQL
PHP
$products = DB::select( "SELECT * FROM products WHERE is_active = 1 ORDER BY created_at DESC" );
أقل وضوحاً عند زيادة الشروط والعلاقات.
أصعب في إعادة الاستخدام والصيانة.
ELOQUENT
PHP
$products = Product::where('is_active', true) ->latest() ->get();
مقروء كأنه إنجليزي بسيط.
سهل إضافة علاقات وفلاتر لاحقاً.
يرتبط مباشرة بالـ Model والعلاقات والـ casts.

Reading Data04 / 08
العمليات الأساسية لجلب البيانات
COMMON METHODS
PHP
Product::all(); Product::all(['id', 'name', 'price']); Product::find(5); Product::findOrFail(5); Product::first(); Product::latest()->first(); Product::orderBy('price', 'asc')->get();
WHEN TO USE
الدالةالاستخدام الأفضل
`all()`قوائم صغيرة أو lookup tables فقط
`find()`عندما تقبل `null` إذا لم يوجد السجل
`findOrFail()`داخل Controllers لصفحات التفاصيل والتعديل
`latest()`قوائم الإدارة والأحدث أولاً
قاعدة عملية: في Controller غالباً اختر `findOrFail()` حتى تحصل على 404 طبيعي بدلاً من أخطاء مبهمة.

Filters05 / 08
كيف نبني فلترة وبحث بدون تعقيد؟
QUERY EXAMPLES
PHP
Product::where('is_active', true)->get(); Product::whereBetween('price', [50, 200])->get(); Product::whereIn('category_id', [1,2,3])->get(); Product::where('is_featured', true) ->orWhere('is_new', true) ->get(); Product::where('name', 'like', "%{$search}%")->get();
MENTAL MODEL
ابدأ دائماً بـ `Product::query()` عندما تتوقع إضافة شروط كثيرة.
كل شرط جديد يضيق النتائج تدريجياً.
ضع البحث النصي في النهاية لتبقى القراءة واضحة.
تجنب كتابة منطق طويل داخل Blade؛ اجمعه في Controller.

Model Safety06 / 08
حماية الـ Model: fillable و casts
FILLABLE
PHP
class Product extends Model { protected $fillable = [ 'category_id', 'name', 'slug', 'description', 'price', 'sale_price', 'stock', 'image', 'is_active' ]; }
WHY IT MATTERS
يمنع المستخدم من تمرير حقول لم تسمح بها مثل `is_admin` أو قيم حساسة.
يجعل `create()` و`update()` آمنين ومقصودين.
CASTS + ACCESSORS
PHP
protected $casts = [ 'is_active' => 'boolean', 'price' => 'decimal:2', 'meta' => 'array', 'published_at' => 'datetime', ];
`casts` تضبط شكل البيانات تلقائياً عند القراءة والكتابة.
Accessor يضيف قيمة جاهزة مثل `formatted_price` للواجهة.
Mutator يعالج الإدخال قبل الحفظ مثل تنسيق الاسم.

Binding07 / 08
ربط الـ Model بالـ Controller عبر Route Model Binding
RESOURCE CONTROLLER
BASH
php artisan make:controller ProductController --resource --model=Product
PHP
public function show(Product $product) { return view('products.show', compact('product')); }
WHY IT'S GOOD
Laravel يجلب السجل تلقائياً من الرابط.
إذا لم يوجد السجل يرجع 404 مباشرة.
التوقيع يصبح أنظف من `show($id)` ثم `findOrFail()`.
هذا سيصبح أساس CRUD كله في المحاضرات القادمة، لذلك افهمه الآن جيداً.
