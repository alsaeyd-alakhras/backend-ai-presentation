Core Concept03 / 09
ما الذي يضيفه Breeze للمشروع؟
BASH
BASH
composer require laravel/breeze --dev
php artisan breeze:install blade
npm install && npm run build
php artisan migrate
WHY
يعطيك مصادقة جاهزة لكن مفهومة، لا يخفي كل التفاصيل.
يعتمد على Blade وSession وهذا مناسب جداً لمرحلة الكورس الحالية.
يبني أساساً ممتازاً قبل الانتقال إلى Fortify لاحقاً.

Implementation04 / 09
كيف نربط حالة المستخدم داخل الواجهة؟
BLADE
BLADE
@auth
  <a href="{{ route('dashboard') }}">حسابي</a>
  <form method="POST" action="{{ route('logout') }}">@csrf<button>خروج</button></form>
@endauth

@guest
  <a href="{{ route('login') }}">دخول</a>
  <a href="{{ route('register') }}">إنشاء حساب</a>
@endguest
DECISION
الطالب يجب أن يرى أثر المصادقة في الـ nav مباشرة.
الربط بـ `@auth` و`@guest` أسهل نقطة لفهم session auth عملياً.
لا نحتاج dashboard معقد الآن؛ المهم إثبات الهوية داخل المتجر.

Best Practice06 / 09
قواعد عملية حتى تبقى بداية الـ auth بسيطة
DO THIS
اعرض فرق الواجهة قبل وبعد login.
اشرح أن Session هي التي تحفظ حالة الدخول في الويب.
خصص صفحات login/register بما يناسب هوية SouqPro.
AVOID
البدء بشرح Fortify قبل فهم auth الأساسية.
إغراق الطالب بملفات كثيرة دفعة واحدة.
ترك صفحات Breeze الافتراضية دون ربطها بالمتجر.

Focus07 / 09
ما الذي يجب أن يفهمه الطالب بعد هذه المحاضرة؟
MENTAL MODEL
المستخدم يسجل أو يدخل مرة واحدة ثم Laravel يتعامل مع الجلسة تلقائياً.
الـ middleware يحمي المسارات لاحقاً بناء على هذه الجلسة.
واجهة المتجر يجب أن تعكس حالة الدخول بشكل مباشر.
NEXT STEP
الآن عندنا auth جاهزة، لكن التخصيص الاحترافي سيأتي مع Fortify.
بعدها سنبدأ حماية المسارات والأدوار والصلاحيات بشكل أعمق.
