Core Concept03 / 09
متى نستخدم Gate ومتى نستخدم Policy؟
GATE
قرار صغير غير مرتبط بموديل محدد.
مثل: هل المستخدم أدمن؟
تعريفه سريع داخل `AppServiceProvider` أو `AuthServiceProvider`.
POLICY
مناسبة عندما نملك Model وأفعالاً متكررة عليه.
مثل: `view`, `create`, `update`, `delete` للمنتجات.
تنظم الصلاحيات في ملف واضح قابل للتوسع.

class ProductPolicy
{
    public function update(User $user, Product $product): bool
    {
        return $user->isAdmin();
    }

    public function delete(User $user, Product $product): bool
    {
        return $user->isAdmin();
    }
}

Best Practice06 / 09
قواعد تجعل الصلاحيات واضحة وسهلة
DO THIS
اربط كل Policy بموديل حقيقي من المشروع.
استخدم `@can` لإخفاء الأزرار لكن لا تعتمد عليه وحده.
اشرح أن الواجهة تجمل التجربة بينما الحماية الحقيقية في backend.
AVOID
وضع كل checks داخل if عشوائية في Controllers.
الاعتماد على إخفاء الزر فقط بدون authorize.
إدخال شروط معقدة كثيرة قبل تثبيت الأساس.
