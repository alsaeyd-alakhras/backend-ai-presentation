Concept — View & Layout3 / 12
إيش هو View؟ وإيش هو Layout؟
View

الصفحة النهائية التي يراها المستخدم في المتصفح — ملف HTML (Blade) يحتوي المحتوى الخاص بشاشة واحدة، مثل صفحة "قائمة المنتجات" أو "لوحة التحكم".

كل View = شاشة واحدة فقط.
Layout

الهيكل العام المشترك بين كل الصفحات — Header وSidebar وFooter تتكرر في كل شاشة. الـ Layout يحمل هذا الهيكل، وكل View يملأ الجزء المتغير فقط.

تكتبه مرة واحدة — تعيد استخدامه في كل صفحة.
لماذا نفصلهم عن بعض؟

بدون Layout — لو عندك 20 صفحة Admin وغيّرت شعار الموقع، لازم تعدّل 20 ملف. مع Layout واحد مشترك، تعدّل مكان واحد وينعكس على كل الصفحات فوراً.

Admin Template4 / 12
تجهيز Admin Template جاهز لـ Laravel
فكرة العملية

نأخذ قالب HTML/Bootstrap جاهز (ملف index.html + مجلدات css/js/images) ونحوّله لبنية Laravel صحيحة.

الخطوات
1 انسخ محتوى index.html إلى ملف View داخل resources/views
2 انقل مجلدات css/ js/ images/ vendor/ إلى public/ كما هي
3 افتح المتصفح — لاحظ أن التصميم يظهر مكسوراً (بدون ألوان ولا JS)
📌 السبب: القالب يستخدم مسارات نسبية مثل href="css/style.css" — وهذا سينكسر لاحقاً عند تغيير الرابط. الحل بالسلايد القادم.

asset() Helper5 / 12
دالة asset() — تصليح روابط الملفات
// المشكلة — مسار نسبي

<!-- يعمل فقط في /dashboard -->
<link href="css/style.css">

<!-- لكن ينكسر في /dashboard/orders -->
<!-- لأن المتصفح يبحث عن: -->
/dashboard/orders/css/style.css ✗ 404
// الحل — asset()

<!-- يبني رابط كامل دائماً -->
<link href="{{ asset('css/style.css') }}">

<!-- ينتج دائماً: -->
http://souqpro.test/css/style.css ✓

// نفس المبدأ لملفات JS والصور
<script src="{{ asset('js/scripts.js') }}"></script>
asset() يبني الرابط دائماً من جذر الموقع (public/) — بغض النظر عن مكان الصفحة الحالية في الروابط.

Controller Intro6 / 12
مقدمة Controller — فكرة MVC مبسّطة
المشكلة قبل Controller

كتابة كل منطق الصفحة داخل routes/web.php مباشرة يجعل الملف يكبر بسرعة ويصعب قراءته وصيانته.

الحل — Controller

كلاس مستقل يحمل منطق الصفحة، ويرجع View جاهزاً. الـ Route فقط يشير إلى الـ method المناسبة.

Terminal
$ php artisan make:controller DashboardController
✓ Controller created successfully.
app/Http/Controllers/DashboardController.php

namespace App\Http\Controllers;

class DashboardController extends Controller
{
  public function index()
  {
    return view('dashboard');
  }
}
⚠️ هذه مقدمة بسيطة فقط — Resource Controllers والـ 7 methods وRoute Groups نؤجلها لمحور 3.

آلية العمل

@extends يقول لهذا الـ View "أنا أعتمد على هذا الـ Layout". @yield('content') هو المكان الفارغ داخل الـ Layout، و@section('content') ... @endsection يملأ هذا المكان بمحتوى الصفحة الحالية.
