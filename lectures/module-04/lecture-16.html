Soft Deletes
احذف بدون أن تفقد البيانات
الحذف الحقيقي خطر في المشاريع الحقيقية. هنا نطبق Soft Deletes داخل SouqPro مع الاستعادة والإدارة الآمنة من لوحة التحكم.

Why Soft Delete02 / 09
ليش الحذف الحقيقي مشكلة؟
Hard Delete
يحذف السجل نهائياً ولا يمكن التراجع.
يكسر تدقيق البيانات والـ audit trail.
قد يربك العلاقات خصوصاً في الطلبات القديمة.
Soft Delete
يضيف قيمة `deleted_at` فقط.
يمكن استعادة السجل بسهولة.
يحافظ على التاريخ والمرجعية داخل النظام.
قاعدة عملية: في الأنظمة التجارية احذف من واجهة المستخدم بـ Soft Delete، والحذف النهائي يكون قرار إداري واضح.

Force Delete05 / 09
متى نستخدم forceDelete()؟
Final Deletion
PHP
$product = Product::withTrashed()->findOrFail($id); if ($product->image) { Storage::disk('public')->delete($product->image); } $product->forceDelete();
Periodic Cleanup
PHP
Product::onlyTrashed() ->where('deleted_at', '<', now()->subDays(30)) ->forceDelete();
استخدم Job مجدول للتنظيف الدوري.
لا تنفذ الحذف النهائي بدون سياسة واضحة.

With Relations06 / 09
Soft Deletes مع العلاقات
Category Model
PHP
protected static function booted(): void { static::deleting(function (Category $category) { $category->products()->each->delete(); }); static::restoring(function (Category $category) { $category->products()->withTrashed()->each->restore(); }); }
Important Note
`cascadeOnDelete()` ينفذ حذف حقيقي على DB level.
مع Soft Deletes عالج الـ cascade في model events.
طبق نفس الفكرة عند وجود علاقات عميقة.

تطبيق عملي داخل لوحة الإدارة
Trashed Screen

public function trashed() { $products = Product::onlyTrashed() ->latest('deleted_at') ->paginate(20); return view('admin.products.trashed', compact('products')); }
Restore Action
PHP
public function restore($id) { Product::withTrashed()->findOrFail($id)->restore(); return back()->with('success', 'تم استعادة المنتج'); }
